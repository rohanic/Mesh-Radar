# Decisions

Every approved change, clarification and dependency for Mesh Radar. The PRD (/docs/PRD.md) wins unless a decision here says otherwise. Entries marked **NEEDS ROHAN** are open and need a decision before release.

## Product

- **DEC-001 Name and package.** Display name "Mesh Radar", Android package `com.meshradar.findgroupoffline`, URL scheme `meshradar://` (Rohan, 2026-10-19; package changed from `com.rohanic.meshradar` and Play title set to "Mesh Radar: Find Group Offline" by Rohan, 2026-10-23; lowercase confirmed by Rohan the same day, by Android convention). The package is permanent after the first Play upload and lives in one constant in `app.config.ts`; JS reads it from the build config. Kotlin source packages (`com.rohanic.meshradar.*`), intent actions and the Nearby service ID are internal names and do not change with it.
- **DEC-002 Hop limit is 7.** Section 4 says "5-hop relay"; D4 and section 8 say 7 hops. We use 7. The header hop count is the number of relays so far; a packet crosses at most TTL links. The event channel and public SOS use 3, join-by-code uses 1 (radio range only).
- **DEC-003 Scope: P0, P1 and P2 together** (Rohan, 2026-10-19). Items only in the "Later" column of section 4 are out of scope: web org dashboard, AR finder, LoRa radio pairing, satellite SOS hand-off, organiser-published packs, community translation, iOS. G7 (event communities) is "Later" in section 4 but P2 in section 5; it is built as a small opt-in P2 feature (Worker-backed posts with report and block).
- **DEC-004 Emergency numbers and translations** (Rohan, 2026-10-19): numbers ship only with an official source link and `verified: false` until a person confirms them; all 8 languages ship as drafts marked unverified; `npm run check:release` blocks a production build until both are verified. The research for numbers and pack dates could only read search results, not open pages, so `docs/emergency-numbers.md` and `docs/event-packs.md` list each source and snippet for the person verifying.

## Protocol and security

- **DEC-005 Envelope.** Sign-then-encrypt: the Ed25519 signature and the sender's 8-byte member ID sit inside the XChaCha20-Poly1305 ciphertext, so relays see only the 32-byte header. The associated data is the header with the hop count zeroed. The 24-byte nonce is derived from the header (16-byte random message ID, created time, version, type, TTL) instead of being sent, saving 24 bytes per packet.
- **DEC-006 Join by code.** The 6-digit code derives a join key. Six digits are easy to brute force offline, so: requests are one-hop only, the creator approves each request on screen, and the group invite is sealed to the joiner's X25519 key with an ephemeral key (a listener who knows the code still cannot read the group key). QR join carries the key directly (B2).
- **DEC-007 Keys.** The identity is a 32-byte seed from libsodium. Ed25519 comes from the seed; X25519 is derived from the seed with BLAKE2b (not converted from Ed25519). The Android Keystore cannot hold Ed25519/X25519 keys on every Android 8+ phone, so the seed is encrypted with an AES-256-GCM key that lives in the Keystore (non-exportable). Delete everything (H4) deletes both.
- **DEC-008 Position packet size.** A sealed position packet is 152 bytes (32 header, 16 IDs, 24 body, 64 signature, 16 MAC), not the ~60 bytes in section 8, which counted the body only. It fits one LE extended advertisement (up to 251 bytes of data), not a legacy 31-byte one. Phones without LE extended advertising (`isLeExtendedAdvertisingSupported` false) skip BLE beacons and use Nearby Connections only.
- **DEC-009 Crypto library.** lazysodium 5.2.0 (`lazysodium-java` for JVM tests, `lazysodium-android` for the app) and JNA 5.17.0, both from Maven Central; libsodium primitives only (section 14). lazysodium 5.2.0 ships Java 21 bytecode, so the JVM core project targets Java 21.
- **DEC-010 Crowd damping.** "Neighbours" means phones discovered in radio range, not only connected ones. With more than 8, damped packet types are rebroadcast with probability 0.7 falling linearly to 0.5 at 24 neighbours, after 50 to 300 ms jitter. SOS, SOS resolve, public SOS, lost-child alerts and Last-Crumb are never damped.
- **DEC-011 Safety packets go out twice.** Priority-0 packets (SOS, SOS resolve, public SOS, lost child) are transmitted twice, 300 ms apart, by the sender and every relay. In the simulator this took SOS delivery within 30 s from 96 % to 99.6 % (see `modules/mesh-engine/core/build/simulator-report.txt` after `npm run core:test`).
- **DEC-012 Nearby Connections radio change.** Google announced (July 2026) that Nearby Connections will stop turning Bluetooth and Wi-Fi on by itself in late 2026. The engine checks both radios before starting and the UI asks the person to turn them on (mesh health sheet and start screen).
- **DEC-013 Public packets.** The event channel and crowd reports are signed with a per-event pseudonymous key derived from the identity seed, so posts cannot be linked across events or to group membership. Public SOS uses a daily pseudonym and carries only a 150 m cell centre; strangers see an 8-point direction and "within about X m". Every app user can open public packets, so relays check signatures and rate limits (1 post per 5 minutes, 1 crowd report per 2 minutes per key) and stop relaying blocked senders.
- **DEC-014 Crowd alert verification.** Verified when 3 distinct per-event keys report the same kind within 200 m of the first report and within 5 minutes of it, or one report carries a valid organiser certificate signed by the licence key. Risk: one person with several phones counts several times; the week-8 drill measures the false-alert rate (target under 5 %).
- **DEC-015 Unknown senders.** Group packets from a member whose MEMBER announcement has not arrived yet are held (50 per sender, 200 senders) and replayed when it arrives, so a Last-Crumb that overtakes the profile is not lost.
- **DEC-016 Licences.** The Worker verifies a Play purchase and returns `base64url(json).base64url(Ed25519 signature)`. Phones verify offline with the public key in `EXPO_PUBLIC_LICENCE_PUBLIC_KEY`. A licence applies to groups whose leader bought it and is shared over the mesh, so one payer unlocks the whole group (section 10, rule 2).

## Architecture and dependencies

- **DEC-017 Data ownership.** The Kotlin engine owns everything the mesh touches (identity, groups, members, messages, pins, SOS, crumbs, breadcrumbs, packet queue) and keeps it while the UI is closed. JS keeps only app settings and content (profile draft, theme, language, packs, badges, memories) in `expo-sqlite/kv-store` through Zustand. Drizzle is not used, and inside the engine plain `SQLiteOpenHelper` replaces Room (no annotation processing to verify). Deviation from the section 8 stack table.
- **DEC-018 Fonts.** `@expo-google-fonts` packages for Inter, Noto Nastaliq Urdu, Noto Naskh Arabic, Noto Sans Devanagari, Noto Sans Bengali, Noto Sans Tamil and Noto Sans Telugu, loaded per active language.
- **DEC-019 Lottie not used yet.** There are no animation assets until the brand question (section 14) is settled. Celebrations use Reanimated. Revisit with the avatar and badge art.
- **DEC-020 i18n.** i18next with its JSON v4 plural keys (CLDR categories through `Intl.PluralRules`) instead of the ICU message format plugin; Crowdin supports this format.
- **DEC-021 Payments.** `expo-iap` 6.1.1 (Expo module from the react-native-iap maintainers) instead of `react-native-iap`.
- **DEC-022 Analytics and crashes.** Both opt-in and off by default. Analytics events queue on the device and go to PostHog's HTTP batch endpoint when online (no SDK); they never include location. Sentry's React Native SDK is initialised only after opt-in and only when a DSN is configured; the source map upload plugin is not added until Rohan creates the Sentry project.
- **DEC-023 Package versions.** Expo SDK 58 set as in Sinew (expo 58.0.14, react-native 0.88.0, reanimated 4.7.1); other Expo packages pinned to the versions in expo 58.0.14 `bundledNativeModules.json`. `@shopify/react-native-skia` 2.14.0, `@sentry/react-native` 8.28.0, `qrcode-generator` 2.0.4 (QR rendering, no native code), `react-native-view-shot` 6.1.1 (memory cards and lost-child wallpaper). Android: `play-services-nearby` 19.3.0 (19.5.0 is built with Kotlin 2.4 metadata that the Kotlin 2.2 toolchain of React Native 0.88 cannot read; CI build of 2026-10-19), `play-services-location` 21.3.0, `androidx.core.uwb:uwb` 1.0.0. Android `compileSdkVersion` 37 and `targetSdkVersion` 36, the React Native 0.88 defaults; Expo SDK 58 libraries fail the AAR metadata check below compileSdk 37 (CI build of 2026-10-19).
- **DEC-037 Plural rules polyfill.** `intl-pluralrules` 2.0.1 (ISC, no dependencies). i18next plurals need `Intl.PluralRules`, and the Hermes Intl documentation lists only Collator, NumberFormat and DateTimeFormat. The polyfill loads only when the engine lacks a working implementation.
- **DEC-038 Worker stack.** Cloudflare Worker in TypeScript with its own `worker/package.json`: `wrangler` 4.145.0 and `@cloudflare/workers-types` 5.20260930.2 (the wrangler peer range), `compatibility_date` 2026-09-30. Workers KV holds signed packs, purchase bindings and first-pilgrimage claims (rare writes, frequent reads). Family Circle mailboxes and event communities are SQLite-backed Durable Objects, one per family and one per event, because KV cannot list "after a cursor" and limits writes. Ed25519 uses the standard Web Crypto `Ed25519` algorithm; the signing key is a 32-byte seed in the `LICENCE_SIGNING_SEED` secret, wrapped as PKCS#8 at runtime. Play purchases are checked with `purchases.products` and `purchases.subscriptionsv2` using a service account.
- **DEC-039 Purchase restores.** One Play purchase can unlock up to 3 identities (new phone, reinstall). One-time passes run from the first redemption, so a later restore does not extend them.
- **DEC-040 Release gate in builds.** `check:release` runs as the `eas-build-post-install` hook and acts only when the EAS production profile sets `MR_RELEASE_GATE=1`. It blocks on unverified numbers, translations and packs, missing public build values, and open NEEDS ROHAN decisions. Missing voice clips are a warning.
- **DEC-046 Internal test builds** (2026-10-23). The `production` EAS profile runs the release gate (DEC-040) and stays blocked until people verify the emergency numbers, packs and translations. The `internal` profile is the same signed release bundle without the gate, for the Play internal testing track only, so the app can be tested on real phones while that verification happens. Unverified numbers keep their "unverified" label in the app. Never promote an `internal` build to production; build again with `production`.
- **DEC-047 Native debug symbols in release bundles** (Rohan, 2026-10-23). Release bundles already run R8 with code and resource shrinking (DEC-041), and the R8 mapping file travels inside the app bundle. Google's guide (developer.android.com/build/include-native-symbols) adds native debug symbols with `android.buildTypes.release.ndk.debugSymbolLevel`; a small config plugin (`plugins/with-native-debug-symbols.js`) sets it to `SYMBOL_TABLE`, the level Google suggests when `FULL` would be large, so it survives `expo prebuild`. Play Console then shows function names for native crashes (Hermes, Skia, libsodium) without manual uploads.
- **DEC-048 Demo data for screenshots** (2026-10-23). `EXPO_PUBLIC_DEMO=1` gives the in-memory engine a sample family group at Mina (an elder, a parent, a sibling and a child at realistic distances, two meeting points, a few messages, 12 nearby phones) for store screenshots and design work in Expo Go. The fake engine never runs in release builds (DEC-042), and no EAS profile sets the flag.
- **DEC-049 Emergency numbers verified against official pages** (Rohan, 2026-10-25). Each number was checked by opening its official page (the country's government site or the UK GOV.UK travel advice); a number is `verified` only when the page shows it for that service, and the exact words are kept in its `evidence` field. 39 numbers passed. 24 whose pages could not be opened or did not show them were removed until a person confirms them (listed in `docs/emergency-numbers.md`); every country keeps a confirmed main line. India 108 was replaced by 102, the National Portal's National Ambulance Service. Labels and country notes now say only what the pages say.
- **DEC-050 Release languages: English and Urdu** (Rohan, 2026-10-25). The other six languages were machine-drafted and PRD section 11 requires native review of safety text, so release builds offer only languages marked `released` in `src/i18n/status.json` (English and Urdu); development builds still show all eight for translators, and Android's per-app language list matches. Rohan reviews the 182 Urdu safety strings himself (`docs/urdu-review.md`) instead of a professional translator; Urdu is marked verified only after his approval. A language is added in an update by reviewing it and setting `released`.
- **DEC-051 Event packs: dates checked, drafts allowed** (Rohan, 2026-10-25). Pack dates were checked against sources: the Islamic dates of Hajj, Umrah, Arbaeen and Muharram all match the official Umm al-Qura calendar, the trekking seasons match the Nepal Tourism Board, and Concerts and Raiwind Ijtema carry no dates; these seven are verified (their emergency numbers come from the verified list). Kumbh, Stadium, Durga Puja, Rath Yatra and Flood and blackout could not be fully confirmed and ship with their visible "Draft, not yet checked" label; the release check warns about them instead of blocking. Verification covers dates and numbers; tips and phrases remain general guidance from the cited sources. The app's Hijri dates now use Umm al-Qura through Intl (the arithmetic calendar showed Hajj starting on the 7th instead of the 8th).
- **DEC-041 Keep rules for minified builds.** Release builds run R8 (`enableMinifyInReleaseBuilds`), and neither `jna` 5.17.0 nor `lazysodium-android` 5.2.0 ships ProGuard rules in its AAR. JNA's native dispatcher looks up classes, fields and methods by name, so the engine module ships consumer rules (`modules/mesh-engine/android/proguard-rules.pro`): the rules from JNA's FAQ ("JNA on Android") and a keep for `com.goterl.lazysodium.**`, as the lazysodium maintainers point to in terl/lazysodium-android#32. Without them a release build either fails on missing `java.awt` classes or crashes on the first libsodium call (A1).

## Safety and Play compliance

- **DEC-024 Full-screen SOS.** Incoming SOS uses a full-screen intent when Android allows it. On Android 14+ Play grants `USE_FULL_SCREEN_INTENT` by default only to calling and alarm apps, so the app checks `canUseFullScreenIntent()` and otherwise shows a high-priority alarm notification. Needs a Play Console declaration.
- **DEC-025 Lock-screen emergency card (A4).** Shown in the persistent notification with public visibility only when the person turns on "Show on lock screen" (default off), with a notice that anyone holding the phone can read it.
- **DEC-026 Family Circle (G6).** Uploads only the same encrypted mesh packets to a Worker mailbox whose ID is an HMAC of the group key; the Worker never sees location in readable form. It runs only while the person has started the engine (foreground service), so no background location permission is needed.
- **DEC-027 Separation alerts are free for everyone** (Rohan, 2026-10-23). Section 10 put them in Event Pass, but rule 1 says never paywall anything that helps someone in danger, and E9 protects Elders and Children. They are now on in every tier, including Free (`Tier.FREE` in `Licences.kt`, `ALWAYS_FREE` in `tiers.ts`), and the plan text lists them under Free. Breadcrumbs (trails) stay in the paid plans.

- **DEC-031 Signed pack updates.** The 12 launch packs are bundled in the app so they work offline from the first launch. When online, the app may fetch a newer copy from the Worker (`/v1/packs/:id.json` and `.sig`); it is installed only if the engine verifies the Ed25519 signature with the licence public key (`verifySignature`). Packs over 2 MB are rejected.
- **DEC-034 First-pilgrimage pass (section 10, rule 3).** The Worker grants one free 14-day Event Pass licence per identity key for a pilgrimage pack (Hajj, Umrah, Arbaeen, Kumbh or Magh Mela). It records only a hash of the public key. Someone can make a new identity to claim again; the cost of that abuse is low and the pass is meant to grow installs.
- **DEC-035 Organiser plan.** Section 10 prices organisers at $0.20 per member per event with a $10 minimum. Play needs fixed products, so there are four one-time products: 50 members ($10), 100 ($20), 250 ($50) and 500 ($100). Each runs for 30 days (one event) and its licence carries the roster size, which the engine enforces. An organiser licence lets the Worker issue an organiser certificate for one event key, which signs crowd alerts (E8).
- **DEC-042 No fake engine in release builds** (Rohan, 2026-10-23). Without the native module the app used an in-memory fake engine, which in a release build would show a working radar and accept an SOS that never leaves the phone. Release builds (`!__DEV__`) now show a full-screen notice instead (`src/features/engine/EngineMissing.tsx`) with the offline emergency numbers for the phone's country and a link to Google Play. Development builds, Expo Go and tests keep the fake.
- **DEC-043 In-app updates** (Rohan, 2026-10-23: "when we update, tell users to update"). Google Play In-App Updates through a small local Expo module (`modules/play-store`, `com.google.android.play:app-update` 2.1.0 from Google Maven, no JS dependency). Flexible flow only: the download runs while the app works, and the restart waits for a tap, because a restart stops the mesh until the person starts it again; Play's immediate flow would block SOS. Never shown during SOS, an urgent alert, Find mode, event day or onboarding, and never offline. "Later" hides an update for 3 days, or 1 day when the release has Play priority 4 or 5 or is 14 days old. Policy and tests: `src/core/engine/updates.ts`. The same module reads the build's version code, which the engine now announces in `MemberBody.appVersion` instead of a fixed 1.
- **DEC-044 In-app review** (Rohan, 2026-10-23). Google Play In-App Review (`com.google.android.play:review` 2.0.2) in the same module. Asked only after a successful regroup or a finished drill, once back on a tab screen, after 3 days and 3 active days, never within 7 days of any SOS, never in Elder mode, at most 3 times and 120 days apart. No question or reward before Play's dialog (Play policy). Policy and tests: `src/core/engine/review.ts`.
- **DEC-036 Event communities moderation (G7).** Posts are opt-in, text only (280 characters), tied to the per-event pseudonymous key, and rate limited to 5 per hour per key. A post hidden by 3 distinct reports stays hidden until reviewed. Each person can block a key on their own phone. No location, photos or links in posts.

## Design

- **DEC-028 Light primary darkened for contrast.** Section 7's light `primary` #00987F with white text measures 3.6:1, below the 4.5:1 AA rule in the same section. Buttons and teal text use #007F6A (4.95:1 on white, 4.65:1 as text on `bg`); #00987F remains the radar sweep colour, where 3:1 for graphics applies. `src/core/theme/contrast.test.ts` checks every text pair in all three themes.
- **DEC-029 Language picker without flags** (decided 2026-10-23; Rohan delegated the call). A2 asks for flags, but flags would be emoji (copy rules forbid them) or images, and languages are not countries: Arabic, Urdu, Hindi, Bengali and Malay each span several, and picking one country's flag for a shared language can offend the others. The picker shows each language in its own script with a two-letter code badge and the "choose your language" line in that language.
- **DEC-030 Placeholder avatar presets.** Section 14 leaves the commissioned illustration set open. The app ships 12 simple vector presets (hijab, turban, cap, ihram, dupatta, elders, a child, kufi and beard, long hair, wheelchair user) drawn in `src/ui/components/Avatar.tsx`, to be replaced by the commissioned set with the same indices.
- **DEC-032 Audio quick replies (section 11).** A quick reply travels as a code, not text, so the receiver plays the clip in their own language (the listener is the one who may not read). Clips must be recorded by native speakers; none are invented. `assets/voice/index.ts` maps language and code to a clip, the play button appears only when a clip exists, and `npm run check:release` lists missing clips.
- **DEC-045 Palette and avatar refresh** (Rohan, 2026-10-23: "follow phone setting", "profile pictures are not good"). Both palettes now follow the Location Pin logo. Light primary is the cyan teal #007A80 (5.1:1 with white text, replacing #007F6A), dark primary is the logo's neon #2CEFD6 on a deeper navy #060B16, and violet accents are brighter. Two tint tokens (`primarySoft`, `accentSoft`) put icons on soft coloured badges instead of grey circles. The light warning colour is darkened to #9A5B00 so it passes AA as text. `contrast.test.ts` now also checks warning and success text, primary text on the background, and icons on the tints. The 12 preset avatars (DEC-030) are redrawn as flat portraits (shoulders and clothing, neck and ears, brows, nose, cheeks, a soft backdrop per preset) with the same indices, so avatars already sent over the mesh still match. The picker grids use even columns (4 on phones, 6 on wide screens), and screens with footer buttons keep room above them for the floating SOS button.
- **DEC-033 Radar rendering.** The radar is one Skia canvas. Blip projection runs in render and the React Compiler memoises it, instead of manual `useMemo`.
